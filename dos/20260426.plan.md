# LitMonitor 可运行 MVP 实施计划

## Summary
在 `/home/data/ljx/bash_hub/litmoniter` 根目录创建完整 `litmonitor` 项目，保留现有 `dos/20260426.md` 作为需求文档。第一版交付可运行 MVP：`pixi` 环境、SQLite 数据库、PubMed 检索、去重入库、规则评分、CLI、FastAPI API、简单 Jinja2 Web、LLM adapter、邮件 digest、APScheduler、Cloudflare/systemd 部署模板、测试和 README。

## Key Changes
- 新增项目骨架：`pixi.toml`、`pyproject.toml`、`.env.example`、`.gitignore`、`README.md`、`src/litmonitor/`、`tests/`、`deploy/`、`data/.gitkeep`。
- 环境管理只使用 `pixi`，定义任务：`init-db`、`lit`、`web`、`web-prod`、`test`、可选 `lint`、`format`。
- 数据层使用 `SQLModel + SQLite`，默认 `DATABASE_URL=sqlite:///./data/litmonitor.db`，模型包括 `Paper`、`SearchProfile`、`SearchRun`、`PaperSearchResult`、`PaperLLMAnalysis`、`Digest`。
- PubMed 数据源使用 NCBI E-utilities，不做网页爬虫；所有外部请求使用 timeout，测试全部 mock。
- CLI 使用 Typer，支持 `init-db`、`search`、`profile add/list/run`、`analyze-paper`、`digest preview/send`、`export`。
- FastAPI 提供 `/health` 和 `/api/v1` REST API；Web 使用 FastAPI + Jinja2，页面包括首页、搜索、profiles、papers、digests、digest preview。
- LLM 模块放在 `services/llm/`，实现统一 backend 抽象，支持 `openai-compatible` 和 `cli` 两类 backend；LLM 失败只记录失败状态，不阻断检索、入库和邮件。
- 邮件使用 SMTP 环境变量配置，生成 HTML 和纯文本 digest，并记录发送成功/失败。
- 部署模板包含 `deploy/cloudflare/config.example.yml`、`deploy/systemd/litmonitor.service.example`、`deploy/systemd/cloudflared-litmonitor.service.example`；README 说明 `litmonitor.example.com -> http://127.0.0.1:8000`，但代码不硬编码域名。

## Public Interfaces
- CLI：
  - `pixi run init-db`
  - `pixi run lit search "query" --since 30d --journal "..."`
  - `pixi run lit profile add/list/run`
  - `pixi run lit analyze-paper --pmid ...` 或 `--paper-id ...`
  - `pixi run lit digest preview/send`
  - `pixi run lit export --format csv|bibtex`
- API：
  - `GET /health`
  - `GET /api/v1/papers`
  - `GET /api/v1/papers/{paper_id}`
  - `POST /api/v1/papers/search`
  - `GET/POST/PATCH/DELETE /api/v1/profiles`
  - `POST /api/v1/profiles/{profile_id}/run`
  - `POST /api/v1/llm/analyze-paper/{paper_id}`
  - `POST /api/v1/llm/analyze-run/{run_id}`
  - `GET /api/v1/papers/{paper_id}/analysis`
  - `POST /api/v1/digests/preview`
  - `POST /api/v1/digests/send`
  - `GET /api/v1/digests`
- `.env.example` 暴露配置：数据库、NCBI API key、APP host/port、SMTP、LLM backend、OpenAI-compatible 参数、CLI backend 参数、LLM 数量和分数限制。

## Implementation Steps
1. 创建项目结构和基础配置，确保 `.gitignore` 排除 `.env`、数据库、日志、Cloudflare 真实配置、凭证、缓存和虚拟环境。
2. 实现配置加载、数据库连接、初始化命令和核心 SQLModel 模型。
3. 实现 `query_builder`、`pubmed`、`dedup`、`ranking`，形成“检索 -> 标准化 -> 去重 -> 评分”的核心 service 流。
4. 实现 LLM schemas、prompt、JSON 解析修复、OpenAI-compatible backend、CLI backend 和 factory。
5. 实现 digest 生成、邮件发送、profile run 编排逻辑，保证 Web/CLI 共用同一套 service。
6. 实现 Typer CLI，再实现 FastAPI API 和简单 Web 页面。
7. 实现 APScheduler：Web 启动时可选择启动 scheduler，每天检查 enabled weekly profiles，避免重复发送已推送论文。
8. 添加 Cloudflare/systemd 模板和完整 README，覆盖 pixi、Git、LLM provider、SMTP、Cloudflare Tunnel、安全注意事项。
9. 编写测试并运行 `pixi run test`，不真实请求 PubMed、LLM provider、Codex CLI 或 SMTP。

## Test Plan
- Query builder：include keywords、journals、exclude keywords、date window 转 PubMed query。
- Dedup：DOI、PMID、PMCID、normalized title、Greek 字符 normalize、title + first author + year。
- Ranking：标题命中、摘要命中、期刊权重、exclude keyword 降分、新鲜度加分。
- PubMed parser：使用 mock XML/JSON 覆盖 DOI 缺失、abstract 缺失、多作者、日期不统一。
- LLM：schema 校验、JSON code block 提取、混杂文本 JSON 提取、非法 JSON 错误、CLI timeout、命令不存在、stdout 非 JSON。
- API/CLI smoke：`init-db`、手动 search mock、profile run mock、`GET /health`。
- 安全检查：确认 `.env`、数据库、Cloudflare credentials、真实 config 不会被 Git 跟踪。
