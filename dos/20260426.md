零、总体设计原则
========================

请严格遵循第一性原则设计。

这个工具的本质不是“做一个网页搜索框”，而是完成以下稳定数据流：

2. 根据策略构建文献检索 query
3. 从可靠 API 获取文献元数据
4. 标准化文献字段
5. 去重入库
6. 根据用户研究兴趣进行规则评分
7. 可选调用 LLM 做简短分析
8. 生成 digest
9. 通过邮件推送
10. 记录哪些文献已推送，避免重复发送

Web 和 CLI 只是两个入口，底层必须复用同一套 service 逻辑。

请减少防御性编码。

这里的“减少防御性编码”指：

- 不要写过度复杂的抽象层。
- 不要为每个理论上可能出现但当前不会处理的情况写大量冗余分支。
- 不要层层包裹 try/except 导致错误被吞掉。
- 不要为了“看起来稳健”牺牲代码可读性。
- 只在必要边界做清晰错误处理：
  - 外部 API 请求
  - 数据库写入
  - 邮件发送
  - LLM 调用
  - subprocess 调用
  - 配置缺失
- 错误处理要清晰、可追踪、不中断主流程中不依赖该步骤的部分。
- LLM 分析失败不能影响文献检索、入库和邮件推送。
- 邮件发送失败要记录状态，而不是静默失败。
- 测试中不要真实请求外部服务，使用 mock。

整体实现应该偏向：
清晰、模块化、可运行、可扩展，而不是过度工程化。

========================
四、核心功能目标
========================

1. 手动检索文献

用户可以通过 CLI 或 Web 输入关键词进行文献检索。

支持指定：

- 关键词 query
- 期刊 journal
- 时间范围 since，例如 7d、30d、2026-01-01:2026-04-01
- 数据源 source，第一版优先支持 PubMed

返回文献信息：

- title
- abstract
- authors
- journal
- publication_date
- doi
- pmid
- pmcid
- source
- url

2. 保存检索策略 Search Profile

用户可以保存一个周期性检索任务。

每个 Search Profile 包含：

- name
- description
- include_keywords
- exclude_keywords
- journals
- source
- date_window，例如 7d
- schedule，例如 weekly
- email_to
- enabled
- min_relevance_score
- llm_enabled

3. 每周自动检索

系统可以根据 Search Profile 自动运行检索任务。
检索过去 7 天或用户指定窗口内的新文献。
需要对文献进行去重，避免每周重复推送。

去重优先级：

1. DOI
2. PMID
3. PMCID
4. normalized title
5. title + first_author + year

4. 相关性评分

对每篇文献计算 relevance_score。

评分因素包括：

- title 中关键词命中
- abstract 中关键词命中
- journal 权重
- exclude keywords 负向过滤
- publication date 新鲜度

第一版使用规则评分，不需要 embedding。

需要保留 matched_keywords，便于邮件中解释为什么推送该论文。

5. 邮件推送

每周自动生成 digest email。

邮件内容包含：

- profile name
- 检索时间
- 文献总数
- Highly relevant papers
- Possibly relevant papers
- 每篇文献的 title、journal、date、doi、pmid、url、matched_keywords、relevance_score
- 如果启用 LLM，则包含 LLM 生成的 short analysis

支持 SMTP 配置。
不要硬编码邮箱密码，使用环境变量或 `.env`。

6. 泛化 LLM 分析接口

LLM 不允许写死为 OpenAI。
需要抽象成统一的 LLM backend / adapter 架构。

第一版至少支持两类 backend：

1. OpenAI-compatible HTTP API backend
2. Local CLI backend

3. 支持 Local CLI backend

我希望这个工具未来可以直接使用我终端中的 Codex 或其他 CLI LLM 工具。

请实现 `cli_backend.py`，允许用户通过环境变量配置一个本地命令：

LLM_CLI_COMMAND=codex
LLM_CLI_ARGS=exec --json
LLM_CLI_TIMEOUT_SECONDS=120

或者：

LLM_BACKEND=cli
LLM_CLI_COMMAND=some-local-llm
LLM_CLI_ARGS=--model local-model --json

CLI backend 逻辑：

- 将完整 prompt 写入 subprocess stdin
- 从 subprocess stdout 读取结果
- 期望 stdout 是 JSON
- 如果 stdout 不是 JSON，尝试从文本中提取第一个 JSON object
- 如果仍失败，记录错误并返回 failed analysis 状态
- subprocess 必须设置 timeout
- 不要把 API key、完整环境变量或隐私信息打印到日志
- 不要默认把所有系统环境变量暴露给子进程；可以继承必要环境，但日志中不得显示敏感内容
- LLM_CLI_COMMAND 和 LLM_CLI_ARGS 都来自配置

CLI backend 的目标是让用户可以自由接入：

- terminal codex
- 自建 LLM wrapper
- 本地 ollama wrapper
- 其他能够从 stdin 接收 prompt 并从 stdout 输出 JSON 的工具

注意：

- 不要假设 codex 一定存在。
- 如果命令不存在，需要给出清晰错误，但不能影响文献检索和邮件发送。

PaperLLMAnalysisResult:

- Do not invent data not present in the title or abstract.

========================
十、Query Builder
========================

请实现 `services/query_builder.py`。

目标是把 SearchProfile 转换为 PubMed query。

例如：

include_keywords:
- pulmonary hypertension
- endothelial
- single-cell

journals:
- Nature Medicine
- Circulation
- American Journal of Respiratory and Critical Care Medicine

exclude_keywords:
- case report
- editorial

应该生成类似：

(
  "pulmonary hypertension"[Title/Abstract]
  OR endothelial[Title/Abstract]
  OR "single-cell"[Title/Abstract]
)
AND
(
  "Nature Medicine"[Journal]
  OR "Circulation"[Journal]
  OR "American Journal of Respiratory and Critical Care Medicine"[Journal]
)
NOT
(
  "case report"[Title/Abstract]
  OR editorial[Title/Abstract]
)

同时支持 date range。

========================
十一、去重逻辑
========================

请实现 `services/dedup.py`。

规则：

1. DOI 相同，认为同一篇。
2. PMID 相同，认为同一篇。
3. PMCID 相同，认为同一篇。
4. normalized_title 相同，认为同一篇。
5. title + first_author + publication_year 相同，认为同一篇。

normalized_title 规则：

- lowercase
- 去除标点
- 合并连续空格
- 替换常见 Greek 字符：
  - β -> beta
  - α -> alpha
  - γ -> gamma
  - κ -> kappa

需要提供函数：

- normalize_title(title: str) -> str
- find_existing_paper(session, paper_candidate) -> Optional[Paper]
- upsert_paper(session, paper_candidate) -> Paper

========================
十二、相关性评分
========================

请实现 `services/ranking.py`。

第一版使用规则评分。

建议：

- title 中命中 include keyword：+5
- abstract 中命中 include keyword：+2
- journal 在高优先级列表：+3
- exclude keyword 命中：-10
- publication date 在 7 天内：+2
- publication date 在 30 天内：+1

输出：

- relevance_score
- matched_keywords
- exclusion_reason，可选

需要支持 profile.min_relevance_score 过滤。

命令示例：

pixi run lit init-db

2. 手动检索

pixi run lit search "pulmonary hypertension endothelial single-cell" --journal "Nature Medicine" --journal "Circulation" --since 30d

3. 创建 profile

pixi run lit profile add \
  --name "PH endothelial weekly" \
  --include "pulmonary hypertension" \
  --include "endothelial" \
  --include "single-cell" \
  --exclude "case report" \
  --exclude "editorial" \
  --journal "Nature Medicine" \
  --journal "Circulation" \
  --journal "American Journal of Respiratory and Critical Care Medicine" \
  --schedule weekly \
  --email your@email.com

4. 查看 profiles

pixi run lit profile list

5. 手动运行 profile

pixi run lit profile run "PH endothelial weekly"

6. 手动运行并发送邮件

pixi run lit profile run "PH endothelial weekly" --send-email

7. 手动运行并启用 LLM 分析

pixi run lit profile run "PH endothelial weekly" --use-llm --send-email

8. 分析单篇论文

pixi run lit analyze-paper --pmid 12345678
pixi run lit analyze-paper --paper-id 1 --profile "PH endothelial weekly"

9. 指定 LLM backend 分析

pixi run lit analyze-paper --paper-id 1 --llm-backend openai-compatible
pixi run lit analyze-paper --paper-id 1 --llm-backend cli

10. 发送 digest 预览

pixi run lit digest preview --profile "PH endothelial weekly"

11. 发送 digest

pixi run lit digest send --profile "PH endothelial weekly"

12. 导出文献

pixi run lit export --profile "PH endothelial weekly" --format csv
pixi run lit export --profile "PH endothelial weekly" --format bibtex

========================
十七、调度器
========================

请实现 `services/scheduler.py`。

MVP 使用 APScheduler。

要求：

1. 启动 Web app 时可以选择启动 scheduler。
2. Scheduler 每天检查 enabled profiles。
3. 对 schedule = weekly 的 profile，每周运行一次。
4. 运行逻辑：
   - 检索文献
   - 去重入库
   - 计算 relevance_score
   - 如果 profile.llm_enabled=true 或 LLM_ENABLED=true，则对高分文献做 LLM 分析
   - 生成 digest
   - 发送邮件
   - 标记 PaperSearchResult.is_sent = true

注意：

- 不要重复发送同一篇论文。
- 如果邮件发送失败，digest 状态应记录 failed。
- 如果某篇文献 LLM 分析失败，不影响其他文献。
- LLM 分析数量必须受 LLM_MAX_PAPERS_PER_RUN 控制。
- 只有 relevance_score >= LLM_MIN_RELEVANCE_SCORE 的论文才默认进入 LLM 分析。

代码应当可以通过以下方式运行：

安装：

pixi install

初始化数据库：

pixi run init-db

手动检索：

pixi run lit search "pulmonary hypertension endothelial single-cell" --since 30d

启动本地 Web：

pixi run web

生产方式启动 Web：

pixi run web-prod

检查服务：

curl http://127.0.0.1:8000/health

Cloudflare Tunnel 示例：

litmonitor.example.com -> http://127.0.0.1:8000

运行 profile：

pixi run lit profile run "PH endothelial weekly" --use-llm --send-email

指定 DeepSeek：

在 .env 中配置：

LLM_ENABLED=true
LLM_BACKEND=openai-compatible
LLM_API_BASE=https://api.deepseek.com/v1
LLM_API_KEY=your_key
LLM_MODEL=deepseek-chat

指定 GLM：

在 .env 中配置：

LLM_ENABLED=true
LLM_BACKEND=openai-compatible
LLM_API_BASE=https://open.bigmodel.cn/api/paas/v4
LLM_API_KEY=your_key
LLM_MODEL=glm-4-plus

指定本地 Codex CLI：

在 .env 中配置：

LLM_ENABLED=true
LLM_BACKEND=cli
LLM_CLI_COMMAND=codex
LLM_CLI_ARGS=exec --json
LLM_CLI_TIMEOUT_SECONDS=120

运行测试：

pixi run test

Git 初始化：

git init
git add .
git commit -m "chore: initialize litmonitor project"
